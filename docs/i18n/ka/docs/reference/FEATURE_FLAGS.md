## რა არის ფუნქციური დროშები

ფუნქციური დროშა არის სახელდებული გადამრთველი (boolean ან enum), რომლის მნიშვნელობაც შეიძლება შეიცვალოს
შესრულების დროს და შენარჩუნდეს მონაცემთა ბაზაში, პროცესის ხელახლა განთავსების საჭიროების გარეშე. თითოეული
დროშა აღწერილია `FeatureFlagDefinition`-ით, რომელსაც აქვს `key`, `label`,
`description`, `category`, `defaultValue`, `type` და `requiresRestart` მინიშნება.

### მნიშვნელობის განსაზღვრის რიგითობა

დროშის **ეფექტური მნიშვნელობა** განისაზღვრება
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts)-ის მიერ შემდეგი
პრიორიტეტით (იმარჯვებს ყველაზე მაღალი):

1. **DB გადაფარვა** — `key_value` ცხრილში, `feature_flags`
   სახელთა სივრცეში შენახული მნიშვნელობა (დაყენებული მართვის პანელიდან ან REST API-დან).
2. **გარემოს ცვლადი** — `process.env[<KEY>]`, თუ დაყენებულია და ცარიელი არ არის.
3. **განსაზღვრების ნაგულისხმევი მნიშვნელობა** — `defaultValue` ფაილიდან `featureFlagDefinitions.ts`.

boolean დროშა **ჩართულად** ითვლება, როცა მისი ეფექტური მნიშვნელობაა `"true"`,
`"1"` ან `"yes"` (იხილეთ `isFeatureFlagEnabled()`).

> [!NOTE]
> დროშების უმეტესობას ასევე აქვს **იმავე სახელის** შესაბამისი გარემოს ცვლადი,
> რომელიც დოკუმენტირებულია [`ENVIRONMENT.md`](./ENVIRONMENT.md)-ში. დროშის DB გადაფარვას
> ამ გარემოს ცვლადზე მაღალი პრიორიტეტი აქვს. დროშა, რომელსაც აქვს
> `requiresRestart: true`, დაუყოვნებლივ ინახება, მაგრამ ხელახლა მხოლოდ პროცესის
> გაშვებისას იკითხება — მისი გადართვისას მართვის პანელში გამოჩნდება ბანერი **"სერვერის გადატვირთვა"**.

## ფლაგების გადართვა

### მართვის პანელი

გადადით **მართვის პანელი → პარამეტრები → ფუნქციური ფლაგები**
(`/dashboard/settings/feature-flags`). ცხრილი
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
მხარს უჭერს:

- **ძიებას** გასაღებით ან აღწერილობით, და **ფილტრაციას** კატეგორიის მიხედვით (პლუს სინთეზური
  **საჭიროებს გადატვირთვას** ხედი).
- **გადამრთველს** ბულიანური ფლაგებისთვის და **ჩამოსაშლელ მენიუს** ენუმერაციული ფლაგებისთვის
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- **წყაროს სამკერდე ნიშანს** თითოეული ფლაგისთვის — `DB`, `ENV`, ან `DEF` — რომელიც აჩვენებს,
  საიდან მოდის ეფექტური მნიშვნელობა.
- **გადატვირთვის** ღილაკს (ნაჩვენებია მხოლოდ `DB`-დან მომდინარე ფლაგებისთვის) გადაფარვის მოსახსნელად,
  და **ყველა გადაფარვის გადატვირთვის** ღილაკს ბოლოში.
- **სერვერის გადატვირთვის** ბანერს, როდესაც `requiresRestart` ფლაგი იცვლება.

### REST API

ყველა ოპერაცია ხორციელდება ერთი მარშრუტის გავლით:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
ყოველი მეთოდი მოითხოვს ავთენტიფიცირებულ მართვის პანელის სესიას (წინააღმდეგ შემთხვევაში `401`).

#### `GET /api/settings/feature-flags`

აბრუნებს ყველა ფლაგს მისი ეფექტური მნიშვნელობით, წყაროთი და შეჯამებით.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... ყველა 77 ფლაგი
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

ადგენს ან შლის ერთ გადაფარვას. სხეული: `{ key: string; value?: string }`.
`value`-ის გამოტოვება შლის გადაფარვას (აღადგენს გარემოს / ნაგულისხმევს).

```bash
# DB გადაფარვის დაყენება
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# გადაფარვის მოხსნა ("value"-ის გარეშე)
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

პასუხი იმეორებს ახალ `effectiveValue`/`source`-ს, `previousValue`/
`previousSource`-ს და `requiresRestart`-ს. უცნობი გასაღებები და დიაპაზონიდან გასული ენუმერაციული
მნიშვნელობები უარყოფილია `400`-ით.

#### `DELETE /api/settings/feature-flags`

აშორებს **ყველა** DB გადაფარვას ერთდროულად, აღადგენს ყველა ფლაგს მის გარემოს / ნაგულისხმევ
მნიშვნელობაზე. აბრუნებს `{ cleared: <count>, message: "..." }`.

> [!შენიშვნა]
> ფლაგები `requiresRestart: true`-ით ძალაში შედის მხოლოდ პროცესის გადატვირთვის შემდეგ.
> მართვის პანელის გადატვირთვის პროცესი იძახებს `POST /api/restart`-ს და შემდეგ ამოწმებს
> `GET /api/health/ping`-ს, სანამ სერვერი არ აღდგება.

## ბიუჯეტის საგანგებო სარეზერვო მექანიზმი

[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
როდესაც ის ჩართულია, მოთხოვნები, რომლებმაც თავიანთი ბიუჯეტი ამოწურეს, პირდაპირ უარყოფის ნაცვლად
უფასო სარეზერვო პროვაიდერთან/მოდელთან გადაიმისამართება. ამ ქცევის გასათიშად და ბიუჯეტამოწურული მოთხოვნების
წარუმატებლად დასასრულებლად დააყენეთ მისი მნიშვნელობა `false`-ზე (ან `0`-ზე) — მართვის პანელის
გადამრთველის, DB-ში მნიშვნელობის გადაფარვის ან `OMNIROUTE_EMERGENCY_FALLBACK`
გარემოს ცვლადის მეშვეობით. (მართვის პანელზე გადამრთველის სახით წარმოდგენილია PR-ებში #3741 / #3752.)
